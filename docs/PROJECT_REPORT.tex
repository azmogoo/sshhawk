\section*{Résumé}

\markboth{Résumé}{Résumé}
\needspace{10\baselineskip}

\begin{resumebox}
Nous avons développé \textbf{SSHawk}, un script Bash qui parcourt les journaux d'authentification SSH,
repère les connexions refusées et produit un rapport synthétique (adresses IP, comptes testés, statistiques).
L'outil s'appuie sur les outils classiques du module (\texttt{grep}, \texttt{awk}, \texttt{curl}\ldots) et reste
\textbf{strictement en lecture seule} : il n'altère ni SSH ni le pare-feu. Les démonstrations de ce rapport
utilisent un fichier d'exemple fictif ; nous n'avons pas versionné de logs réels.
\end{resumebox}

\section{Contexte du projet}
\needspace{4\baselineskip}

Dans le cadre du module \emph{Introduction à Linux} (Monsieur CAPIOD), nous devions produire un script Bash
exploitant les outils du terminal sur un cas concret. Nous avons développé \textbf{SSHawk} pour analyser
automatiquement les tentatives SSH échouées dans les journaux système.

\begin{pointbox}[Objectifs]
  \begin{itemize}[leftmargin=*,noitemsep]
    \item Lire \texttt{auth.log}, \texttt{journalctl} ou un fichier de test ;
    \item Extraire les IP et identifiants concernés, puis agréger les statistiques ;
    \item Produire un rapport Markdown ou texte (\texttt{reports/}), en lecture seule.
  \end{itemize}
\end{pointbox}

% =============================================================================
\section{Pourquoi les logs SSH ?}

Sur notre VM de développement, le service SSH est actif : en quelques heures, les journaux contiennent déjà
des tentatives depuis des IP variées. Ce n'est pas forcément une attaque ciblée ; la plupart du temps, ce sont
des robots qui scannent le port 22. Malgré tout, savoir \emph{qui} est visé (\texttt{root}, \texttt{admin}\ldots)
et \emph{depuis où} aide à décider si l'on durcit la configuration ou si l'on contacte l'administrateur réseau.

Ce sujet nous a permis de mobiliser exactement ce que le cours met en avant :
\begin{itemize}[leftmargin=*]
  \item manipulation de fichiers système et droits (\texttt{sudo} pour \texttt{auth.log}) ;
  \item chaînage \texttt{grep} / \texttt{awk} / \texttt{sort} / \texttt{uniq} ;
  \item structuration d'un script Bash (fonctions, options, gestion d'erreurs avec \texttt{set -euo pipefail}) ;
  \item un premier contact avec \texttt{curl} et une API HTTP publique pour la géolocalisation.
\end{itemize}

\section{Ce que disent les logs SSH}
\Needspace{18\baselineskip}

OpenSSH écrit dans syslog des messages normalisés. SSHawk se concentre sur les lignes qui signalent un échec,
par exemple :

\begin{itemize}[leftmargin=*]
  \item \texttt{Failed password for ... from} une adresse IP
  \item \texttt{Invalid user ... from} une adresse IP
  \item \texttt{Failed publickey for ...}
  \item \texttt{authentication failure} avec \texttt{user=...}
\end{itemize}

Chaque événement peut contenir une IPv4, une IPv6 (\texttt{2001:db8::1} dans notre sample), un identifiant
et un horodatage. Le script isole d'abord les lignes \texttt{sshd}, puis applique plusieurs expressions régulières
car le format exact change légèrement selon le type d'échec.

\section{Fonctionnement de SSHawk}

\subsection{Chaîne de traitement}

\begin{enumerate}[leftmargin=*]
  \item \textbf{Entrée} — selon \texttt{--source} : fichier local, \texttt{auth.log} ou flux \texttt{journalctl}.
  \item \textbf{Filtrage} — conservation des messages d'échec connus (mot de passe, clé, utilisateur invalide\ldots).
  \item \textbf{Parsing} — pour chaque ligne : IP via \texttt{extract\_ip\_from\_line}, utilisateur si présent.
  \item \textbf{Agrégation} — totaux par IP, fenêtre temporelle, classement des comptes les plus ciblés.
  \item \textbf{Géolocalisation} — optionnelle (\texttt{--no-geo} pour les tests) avec temporisation entre requêtes.
  \item \textbf{Sortie} — rapport horodaté dans \texttt{reports/} (format \texttt{md} ou \texttt{txt}).
\end{enumerate}

\subsection{Organisation du code}

Le cœur du projet est \texttt{sshawk.sh} : plutôt qu'un seul bloc de commandes, nous avons découpé le script
en fonctions (\texttt{collect\_logs}, \texttt{parse\_log\_line}, \texttt{generate\_report}\ldots) pour faciliter
les tests et la relecture. Un fichier \texttt{config/sshawk.conf} centralise les chemins par défaut.

\subsection{Extensions prévues au-delà du minimum}

\begin{itemize}[leftmargin=*]
  \item Prise en charge IPv6 et patterns supplémentaires (\texttt{keyboard-interactive}, etc.) ;
  \item Script \texttt{run\_scheduled\_report.sh} et exemples systemd/cron (\texttt{systemd/}, \texttt{scripts/}) pour
        lancer un rapport périodique sur un serveur de test.
\end{itemize}

\section{Difficultés et ce que nous en avons retiré}
\Needspace{16\baselineskip}

\begin{pointbox}[Points techniques]
  \begin{itemize}[leftmargin=*]
    \item \textbf{journalctl} — le nom de l'unité change (\texttt{ssh} vs \texttt{sshd}) ; nous testons les deux.
    \item \textbf{Formats hétérogènes} — le nom d'utilisateur n'apparaît pas toujours au même endroit dans la ligne.
    \item \textbf{Mode strict Bash} — le \texttt{trap} de fin devait gérer \texttt{\$\{tmpdir:-\}} pour éviter un crash avec \texttt{set -u}.
    \item \textbf{API de géoloc} — parfois \texttt{Unknown} ; nous utilisons \texttt{--no-geo} en démo pour ne pas dépendre du réseau.
    \item \textbf{Captures d'écran} — \texttt{head reports/*.md} mélange tous les fichiers ; nous ciblons le plus récent avec \texttt{ls -1t}.
  \end{itemize}
\end{pointbox}

\needspace{5\baselineskip}
Au-delà des bugs, ce projet nous a habitués à lire de vrais messages syslog et à documenter nos choix
(README, tests, rapport) comme on le ferait sur un petit outil d'équipe.

% =============================================================================
\section{Confidentialité}

\begin{alertbox}
Les journaux d'un serveur en production peuvent révéler des IP réelles, des comptes internes ou des plages horaires sensibles.
Nous avons volontairement limité le dépôt Git au fichier \texttt{sample-auth.log} et aux rapports générés localement
(ignorés par \texttt{.gitignore}). SSHawk \textbf{n'écrit jamais} dans \texttt{/etc/ssh} ni ne bloque d'adresse :
il produit uniquement un rapport à consulter.
\end{alertbox}
